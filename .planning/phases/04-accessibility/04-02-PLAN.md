   - `aria-label={`${node.label}, niveau ${node.level}, famille ${node.family}`}`
   - `onFocus={() => onHoverChange?.(node.id)}` — reuses existing hover/tooltip mechanism

   ```tsx
   {
     isFocused && (
       <circle
         r={r + 5}
         fill="none"
         stroke="white"
         strokeWidth={2}
         strokeDasharray="4 2"
         opacity={0.85}
       />
     );
   }
   ```
4. IMPORTANT: Do NOT add tabIndex to any child elements (circle, svg icon, text) — only the outer `<g>` is the focus target. This avoids focus bubbling issues (Pitfall 2 from research).

**StackGraph.tsx changes:**

1. Add `keyboardFocusedId` state: `const [keyboardFocusedId, setKeyboardFocusedId] = useState<string | null>(null)`
2. Create two callback functions:
   - `handleNodeFocus = (id: string | null) => { setKeyboardFocusedId(id); setHoveredId(id); }` — sets both focus ring AND tooltip
   - Keep existing `setHoveredId` for pointer hover (onHoverChange on GraphNode stays for pointer events)
3. PROBLEM: GraphNode has a single `onHoverChange` prop used by both pointer and focus. To differentiate:
   - Add a new prop `onFocusChange?: (id: string | null) => void` to GraphNodeProps
   - In GraphNode: `onFocus={() => { onHoverChange?.(node.id); onFocusChange?.(node.id); }}` and `onBlur={() => { onHoverChange?.(null); onFocusChange?.(null); }}`
   - In StackGraph: pass `onFocusChange={setKeyboardFocusedId}` to GraphNode
   - Pass `isFocused={keyboardFocusedId === pos.id}` to GraphNode
4. Clear keyboardFocusedId when focused node is filtered out (add to existing `activeNodeIds` effect)
