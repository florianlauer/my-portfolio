# Phase 6 — Plan 06-02: Touch gestures pour zoom/pan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Permettre au visiteur de zoomer (pinch) et de pan (drag) le Stack Graph sur écran tactile, sans régression desktop, sans bloquer le scroll de la page en dehors du graph, et sans casser le drag de nœuds individuels.

**Architecture:** d3-zoom est déjà attaché au SVG (StackGraph.tsx, useEffect lignes 138-165) et gère wheel + mousedown via une fonction `filter()` qui requiert `event.target === bgRect` pour démarrer un pan. Le filter actuel **bloque le pinch tactile multi-touch dès que le premier doigt tombe sur un nœud**, parce qu'il n'examine pas `event.touches.length`. On étend `filter()` pour autoriser explicitement les `touchstart` multi-touch quel que soit le target. Côté CSS, on applique `touch-action: none` sur le SVG : sans cette directive, le navigateur consomme les touch events natifs (pan-y / pinch-zoom du browser) avant que d3-zoom ne les voie, ce qui résulte en zoom de la page entière au lieu du graph. `touch-action: none` est posé **uniquement sur le SVG**, pas sur le conteneur — le scroll vertical de la page reste possible quand le doigt est ailleurs (ex. sur les filter pills, la légende, le reste de la page). Le drag de nœud (PointerEvent dans `GraphNode`) continue à fonctionner car `setPointerCapture` capture l'événement avant que d3-zoom ne le voie, et `e.stopPropagation()` est déjà appelé dans `handlePointerDown`.

**Tech Stack:** Next.js 16, React 19, TypeScript. d3-zoom (déjà installé). Pas de nouvelle dépendance. Aucune lib externe pour les gestures (Hammer.js, etc.) — d3-zoom v3 supporte multi-touch nativement.

## Task 1: Update d3-zoom filter to allow multi-touch pinch

**Files:**

- Modify: `src/components/stack-graph/StackGraph.tsx`

- [ ] **Step 1: Locate the existing zoom filter and replace it**

Localise dans `src/components/stack-graph/StackGraph.tsx` le bloc qui configure d3-zoom (lignes ~144-155) :

```tsx
const zoomBehavior = zoom<SVGSVGElement, unknown>()
  .scaleExtent([0.5, 3])
  .filter((event) => {
    // Wheel: always allow (zoom + preventDefault page scroll)
    if (event.type === "wheel") return true;
    // Pan: only when initiated on the background rect, not on a node
    return event.target === bgRect;
  })
  .on("zoom", (event) => {
    // Direct DOM mutation — no setState, no React re-render
    innerG.setAttribute("transform", event.transform.toString());
  });
```

Remplace le bloc `.filter(...)` par :

```tsx
.filter((event) => {
  // Wheel: always allow (zoom + preventDefault page scroll)
  if (event.type === "wheel") return true;
  // Multi-touch (pinch): always allow, regardless of target.
  // d3-zoom aggregates touchstart → touchmove → touchend across the SVG
  // and computes a pinch zoom transform from the two-finger spread.
  // We can't restrict pinch to bgRect because the user may naturally
  // place their fingers on/around nodes when pinching to zoom in.
  if (event.type === "touchstart" && event.touches && event.touches.length >= 2) {
    return true;
  }
  // Pan (single touch / mousedown): only when initiated on the background rect,
  // not on a node. Node drags handle their own PointerEvent capture and
  // bubble through stopPropagation, so they never reach this filter.
  return event.target === bgRect;
})
```

Justification : `event.touches` est défini sur les TouchEvents (touchstart, touchmove). Sur les MouseEvents/PointerEvents il est `undefined`, d'où le guard `event.touches && ...`. d3-zoom v3 dispatch les TouchEvents bruts au filter — pas de wrapper, on lit `touches.length` directement.

⚠️ Note : si TypeScript proteste sur `event.touches` (parce que `event` est typé `D3ZoomEvent`), c'est attendu — d3-zoom passe le DOM Event sous-jacent au filter, donc cast en `TouchEvent` au besoin :

```tsx
if (event.type === "touchstart") {
  const touchEvent = event as TouchEvent;
  if (touchEvent.touches && touchEvent.touches.length >= 2) return true;
}
```

Utiliser cette forme typée si le build échoue sur la version courte.

Run: `npm run lint && npm run fmt:check && npm run build`
Expected: OK. Si erreur TS sur `event.touches`, applique le cast typé décrit en Step 1.

## Task 2: Add `touch-action: none` on the SVG element

**Files:**

- Modify: `src/components/stack-graph/StackGraph.tsx`

- [ ] **Step 1: Locate the SVG opening tag**

Localise dans `src/components/stack-graph/StackGraph.tsx` le `<svg>` à l'intérieur du conteneur (vers ligne 363-369) :

```tsx
<svg
  ref={svgRef}
  viewBox={`0 0 ${size.width} ${size.height}`}
  className="w-full h-full"
  overflow="hidden"
  aria-hidden="true"
>
```

- [ ] **Step 2: Add `touch-action: none` via inline style**

Remplace par :

```tsx
<svg
  ref={svgRef}
  viewBox={`0 0 ${size.width} ${size.height}`}
  className="w-full h-full"
  overflow="hidden"
  aria-hidden="true"
  style={{ touchAction: "none" }}
>
```

Justification :

- `touch-action: none` désactive **tous les gestures natifs du navigateur** (pan-y page scroll, pinch-zoom page) **uniquement sur le SVG**. Le scroll de la page reste possible quand le doigt n'est pas sur le SVG (filter pills, légende, header, footer, etc.).
- Sans cette directive, sur Safari iOS notamment, le browser intercepte le pinch et zoome la viewport entière, ignorant d3-zoom complètement. C'est le piège classique du double-touch web.
- On applique via `style={{ touchAction: "none" }}` plutôt que via classe Tailwind (`touch-none`), car Tailwind v4 le supporte via `touch-none` mais le `style` inline garantit la priorité CSS.

Alternative équivalente avec Tailwind : ajouter `touch-none` à `className` :

```tsx
className = "w-full h-full touch-none";
```

— les deux fonctionnent. Préfère le style inline pour la clarté de l'intention (« this is here for d3-zoom, not for visual layout »).

## Notes pour l'exécutant

**Pourquoi pas Hammer.js / use-gesture / autre lib ?**
d3-zoom v3 gère déjà multi-touch nativement. Ajouter une lib introduirait un risque de conflit avec les PointerEvents de drag de nœud (deux gestionnaires se disputeraient les mêmes events). Le fix de 6 lignes dans le filter est suffisant.

**Pourquoi `touch-action: none` plutôt que `pan-y pinch-zoom: none` ?**
On veut désactiver **tous** les gestures natifs du browser sur le SVG :

- `touch-action: pan-y` : autorise scroll vertical → empêche d3-zoom de pan (browser consomme avant)
- `touch-action: pan-x pan-y` : pareil
- `touch-action: pinch-zoom` : autorise pinch browser → zoom de la viewport entière, pas du graph
- `touch-action: none` : désactive tout → d3-zoom voit tous les events ✅

**Pourquoi tester sur device réel ?**
Chrome DevTools "Toggle device toolbar" simule la viewport mais utilise des PointerEvents single-touch. Le multi-touch (pinch, deux doigts) **n'est pas simulable**. Pareil pour `touch-action` : DevTools les respecte mais le comportement Safari iOS / Android Chrome diffère subtilement. Vérification sur device = obligatoire pour valider MOBILE-02.

**Si pas de device tactile disponible :**
Utiliser BrowserStack ou un émulateur Android (`adb` + Chrome remote debug). En dernier recours, BrowserStack Live offre 5 min gratuites pour tester sur iPhone réel — suffisant pour valider les 9 steps du Task 3.
