# Phase 5 — Plan 05-01: Entry Animation + Node Sizing

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Faire apparaître progressivement les nœuds du graph au premier render et garantir que la taille du nœud reflète visiblement le niveau d'expérience.

**Architecture:** Animation d'entrée pilotée par CSS transitions (opacity + scale), déclenchée par un state `entered` dans `StackGraph` qui passe à `true` au mount via `requestAnimationFrame` + `setTimeout`. Les nœuds reçoivent un `enterDelay` calculé depuis leur index pour un effet stagger. Le mode `prefers-reduced-motion` saute l'animation entièrement (entered = true au mount, transition désactivée). La taille des nœuds (POLISH-02) est déjà pilotée par `NODE_RADIUS_BY_LEVEL` dans `constants.ts` ; ce plan vérifie la lisibilité visuelle et ajuste les rayons si nécessaire.

**Tech Stack:** Next.js 16, React 19, TypeScript, Tailwind v4, d3-force (existant). Pas de nouvelle dépendance — `motion` (Framer Motion) est installée mais non utilisée ici (CSS suffit).

**Requirements:** POLISH-01, POLISH-02
**Files modified:** `src/components/stack-graph/StackGraph.tsx`, `src/components/stack-graph/GraphNode.tsx`, `src/components/stack-graph/constants.ts`

- [ ] **Step 2: Add effect to flip `entered` to true after first paint**

Insère ce useEffect AVANT le `useEffect` du `ResizeObserver` (ligne 67) :

```tsx
// Trigger entry animation on next paint. requestAnimationFrame ensures the
// initial render with entered=false commits to the DOM before we flip,
// so the CSS transition has both states to interpolate between.
// Reduced motion: skip the delay, set entered immediately (transition is
// also disabled in GraphNode under reducedMotion, see Task 2).
useEffect(() => {
  if (reducedMotion) {
    setEntered(true);
    return;
  }
  let rafId: number | null = null;
  const timeoutId = window.setTimeout(() => {
    rafId = window.requestAnimationFrame(() => setEntered(true));
  }, 50);
  return () => {
    window.clearTimeout(timeoutId);
    if (rafId !== null) window.cancelAnimationFrame(rafId);
  };
}, [reducedMotion]);
```

- [ ] **Step 3: Replace the root `<g>` opacity/transition style with the combined entry style**

Remplace les lignes 121-124 (`<g transform=... className=... style={{ opacity: opacity ?? 1, transition: "opacity 200ms ease" }}`) par :

```tsx
<g
  transform={`translate(${x}, ${y})`}
  className="cursor-grab active:cursor-grabbing"
  style={{
    opacity: entered ? (opacity ?? 1) : 0,
    transform: entered ? "scale(1)" : "scale(0.5)",
    transformOrigin: "center",
    transformBox: "fill-box",
    transition: reducedMotion
      ? "none"
      : `opacity 400ms ease ${enterDelay}ms, transform 400ms cubic-bezier(0.34, 1.56, 0.64, 1) ${enterDelay}ms, opacity 200ms ease`,
  }}
```

Note: la double déclaration `opacity ... ease ${delay}` puis `opacity 200ms ease` à la fin produit deux transitions concaténées sur la même propriété — la dernière gagne pour le focus dimming après l'entrée. C'est intentionnel : pendant l'entrée on respecte le delay, ensuite les changements d'opacity (dimming au focus) sont fluides à 200 ms.

⚠️ Le `transform` était déjà utilisé pour le translate. On le déplace dans `style` pour pouvoir composer avec `scale`. Solution : laisser `transform={...}` côté SVG (translate au niveau du group), et appliquer `scale` via CSS sur la propriété `transform` du style (qui surcharge l'attribut). **Mais** mélanger attribute et style sur `transform` est ambigu. La méthode propre : utiliser un `<g>` parent pour translate, et un `<g>` enfant pour scale :

Remplace tout le `return (` jusqu'à la fin (lignes 120-166) par :

```tsx
  return (
    <g transform={`translate(${x}, ${y})`}>
      <g
        className="cursor-grab active:cursor-grabbing"
        style={{
          opacity: entered ? (opacity ?? 1) : 0,
          transform: entered ? "scale(1)" : "scale(0.5)",
          transformOrigin: "0 0",
          transformBox: "fill-box",
          transition: reducedMotion
            ? "none"
            : `opacity 400ms ease ${enterDelay}ms, transform 400ms cubic-bezier(0.34, 1.56, 0.64, 1) ${enterDelay}ms`,
        }}
        onPointerDown={handlePointerDown}
        onPointerMove={handlePointerMove}
        onPointerUp={handlePointerUp}
        onPointerEnter={() => onHoverChange?.(node.id)}
        onPointerLeave={() => onHoverChange?.(null)}
      >
        {/* Hit area: invisible circle that guarantees a 44×44 touch target */}
        <circle r={hitRadius} fill="transparent" pointerEvents="all" />

        {/* Visible circle — drop-shadow filter is hoisted into StackGraph <defs> as glow-${family} */}
        <circle r={r} fill={color} fillOpacity={0.95} filter={`url(#glow-${node.family})`} />

        {/* Icon or abbreviation */}
        {icon ? (
          <svg
            x={-iconSize / 2}
            y={-iconSize / 2}
            width={iconSize}
            height={iconSize}
            viewBox={icon.viewBox}
          >
            <path d={icon.path} fill="white" />
          </svg>
        ) : (
          <text
            x={0}
            y={0}
            textAnchor="middle"
            dominantBaseline="central"
            fill="white"
            fontSize={Math.min(
              Math.round(r * 0.7),
              Math.round((r * 1.6) / Math.max(shortLabel.length * 0.55, 1)),
            )}
            fontWeight={600}
            fontFamily="var(--font-dm-sans)"
          >
            {shortLabel}
          </text>
        )}
      </g>
    </g>
  );
}
```

Pourquoi deux `<g>` imbriqués : le parent applique `translate(x, y)` (attribute SVG, suit la simulation d3), l'enfant applique `scale` + `opacity` via `style` (animation CSS d'entrée). Pas de conflit, pas d'ambiguïté.

⚠️ Le hover handler était sur le `<g>` racine. Maintenant il est sur le `<g>` enfant. Vérifie que `onPointerEnter`/`onPointerLeave` reçoivent toujours les bons events — ils bubbleront depuis les `<circle>` enfants.
