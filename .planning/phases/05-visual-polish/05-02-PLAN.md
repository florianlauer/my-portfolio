# Phase 5 — Plan 05-02: Preset "ma stack typique" + Edge Focus Animation

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Permettre au visiteur d'activer en un clic un preset "ma stack typique" qui met en avant un sous-ensemble curé de nœuds, et animer les edges connectés au nœud focus pour mieux faire ressortir les relations.

**Architecture:** Un nouveau pill "Ma stack typique" dans `GraphFilters` toggle un état `presetActive` au niveau de `StackGraph`. Quand actif, l'opacity des nœuds non-preset descend à 0.2 (les autres restent à 1). Le preset est **purement visuel** — il ne touche pas `activeFilters` (les pills frontend/backend/devops continuent à fonctionner indépendamment). Pour les edges, on étend `GraphEdge` avec une prop `highlighted` qui passe le `strokeWidth` de 1.5 → 3 et `strokeOpacity` de 0.35 → 0.85, plus une animation `<animate>` SVG (pulse léger) désactivée sous reducedMotion.

**Tech Stack:** Next.js 16, React 19, TypeScript, Tailwind v4. Pas de nouvelle dépendance. SVG `<animate>` natif suffit (pas de Framer Motion).

**Requirements:** POLISH-03, POLISH-04
**Files modified:** `src/content/stack-graph.ts`, `src/types/stack-graph.ts`, `src/components/stack-graph/StackGraph.tsx`, `src/components/stack-graph/GraphFilters.tsx`, `src/components/stack-graph/GraphEdge.tsx`, `src/messages/{fr,en,de}.json`

- [ ] **Step 2: Render strokeWidth + animation conditionally**

Remplace la fonction entière (lignes 9-28) par :

```tsx
export function GraphEdge({
  x1,
  y1,
  x2,
  y2,
  opacity,
  highlighted = false,
  reducedMotion = false,
}: GraphEdgeProps): React.JSX.Element {
  const dx = x2 - x1;
  const dy = y2 - y1;
  const cx1 = x1 + dx * 0.25;
  const cy1 = y1 + dy * 0.1;
  const cx2 = x1 + dx * 0.75;
  const cy2 = y2 - dy * 0.1;
  const d = `M ${x1} ${y1} C ${cx1} ${cy1}, ${cx2} ${cy2}, ${x2} ${y2}`;

  const stroke = highlighted ? "var(--foreground)" : "#888";
  const strokeWidth = highlighted ? 3 : 1.5;
  const strokeOpacity = highlighted ? 0.85 : 0.35;

  return (
    <path
      d={d}
      stroke={stroke}
      strokeOpacity={strokeOpacity}
      strokeWidth={strokeWidth}
      fill="none"
      style={{
        opacity: opacity ?? 1,
        transition: reducedMotion
          ? "opacity 200ms ease"
          : "opacity 200ms ease, stroke-width 200ms ease, stroke-opacity 200ms ease",
      }}
    >
      {highlighted && !reducedMotion && (
        <animate
          attributeName="stroke-opacity"
          values="0.85;1;0.85"
          dur="1.6s"
          repeatCount="indefinite"
        />
      )}
    </path>
  );
}
```

Justification :

- `var(--foreground)` (oklch defined dans globals.css) garantit un contraste élevé sur fond clair/sombre. Pour un edge "neutral but bold", le foreground est plus lisible que la couleur de famille (qui ferait visuellement gagner une famille).
- `<animate>` SVG tourne sur le compositor browser (pas de re-render React, pas de `requestAnimationFrame` JS). Aucun coût CPU mesurable.
- Sous `reducedMotion`, `<animate>` n'est jamais monté → conforme WCAG 2.3.3.

- [ ] **Step 1: Compute `isHighlighted` per edge in the render loop**

Localise la map des edges (lignes 364-378). Remplace par :

```tsx
{
  data.edges.map((edge) => {
    const source = posMap.get(edge.source);
    const target = posMap.get(edge.target);
    if (!source || !target) return null;
    const isHighlighted =
      neighborSet !== null && neighborSet.has(edge.source) && neighborSet.has(edge.target);
    return (
      <GraphEdge
        key={`${edge.source}-${edge.target}`}
        x1={source.x}
        y1={source.y}
        x2={target.x}
        y2={target.y}
        opacity={getEdgeOpacity(edge.source, edge.target)}
        highlighted={isHighlighted}
        reducedMotion={reducedMotion}
      />
    );
  });
}
```

Logique : un edge est highlighted **uniquement** quand un nœud est focus (`neighborSet !== null`) ET que les deux endpoints sont dans le `neighborSet`. Le neighborSet contient le focus + ses voisins directs → seuls les edges connectés au nœud focus passent. Le preset n'active pas le highlight pour éviter une cascade visuelle (preset → 14 nœuds → ~30 edges qui pulsent simultanément, trop bruyant).
