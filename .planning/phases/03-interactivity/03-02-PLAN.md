**A. Create GraphTooltip.tsx** — HTML overlay positioned above the hovered node:

Props: `{ node: GraphNode | null; neighbors: { id: string; label: string; family: StackFamilyKey }[]; position: { x: number; y: number }; visible: boolean; familyColorMap: Map<StackFamilyKey, string> }`

Structure:

- `position: absolute` div inside StackGraph's `relative` container
- Positioned via `style={{ left: pos.x, top: pos.y, transform: "translate(-50%, -100%)" }}` (centered above node)
- Animation: Tailwind classes `transition-all duration-150 ease-out`. When visible: `opacity-100 scale-100`. When hidden: `opacity-0 scale-95 pointer-events-none`.
- Content layout:
  - Header: `<strong>{node.label}</strong>` + level badge (e.g., `<span className="text-xs bg-white/10 px-2 py-0.5 rounded-full">{node.level}</span>`)
  - Description: `<p className="text-xs text-foreground/70">{node.description}</p>`
  - Connected techs: flex-wrap row of tags, each with a small colored dot (color from familyColorMap by the neighbor's family) + label text. Use `cn()` for conditional classes.
- Max-width: 280px. `rounded-xl border border-border bg-popover/95 backdrop-blur-sm p-3 shadow-lg`
- Viewport clamping: after computing position, clamp x to `[8, containerWidth - 288]`. If `y - tooltipHeight < 8`, flip below node (add `transform: "translate(-50%, 12px)"` instead of `-100%`). Use a ref to measure tooltip height after render.

**B. Tooltip positioning logic in StackGraph.tsx:**

- Add `const [hoveredId, setHoveredId] = useState<string | null>(null)`
- Pass `onHoverChange={setHoveredId}` to each GraphNode (Plan 01 already added this callback)
- Compute tooltip data: when hoveredId changes, find the node, find its neighbors from edges, get their labels/families
- Compute screen position: use the hovered node's SVG coordinates + the current `transformRef.current` (zoom transform). Convert SVG coords to container-relative coords using `innerGRef.current.getScreenCTM()`:
  ```
  const pt = svgRef.current.createSVGPoint();
  pt.x = nodeX; pt.y = nodeY - nodeRadius - 12;
  const screenPt = pt.matrixTransform(innerGRef.current.getScreenCTM());
  const containerRect = containerRef.current.getBoundingClientRect();
  position = { x: screenPt.x - containerRect.left, y: screenPt.y - containerRect.top };
  ```
  This correctly accounts for zoom transform since getScreenCTM() on the inner `<g>` includes the zoom transform attribute.
- Recalculate position on zoom: in the zoom event handler (from Plan 01), if hoveredId is set, trigger a position recalculation. Use a `requestAnimationFrame` or simply re-run the position computation in the zoom callback.
- Render `<GraphTooltip>` as a sibling to the SVG inside the `relative` container div

**C. Create GraphFilters.tsx** — Toggle pill buttons:

Props: `{ filters: { key: string; label: string; color: string }[]; activeFilters: Set<string>; onToggle: (key: string) => void }`

- 3 pills for: `{ key: "frontend", label: "Frontend", color: <derived from familyColors for "frontend"> }`, `{ key: "backend", label: "Backend", color: <from "backend"> }`, `{ key: "devops", label: "DevOps", color: <from "infra"> }`
- Each pill: `<button>` with a small colored dot + label. Active state: `bg-foreground/10 text-foreground border-foreground/20`. Inactive: `bg-transparent text-foreground/40 border-border`. Use `cn()`.
- Flex row with `gap-2`, positioned above the graph. Add it in `page.tsx` between the `<h1>` and `<StackGraph>`, OR inside StackGraph above the SVG.
- `onToggle` handler: if toggling OFF and only 1 filter is active, do nothing (enforce at-least-1 rule)

**D. Filter state and d3-force dynamic update:**

- In `StackGraph.tsx`, add `const [activeFilters, setActiveFilters] = useState<Set<string>>(new Set(["frontend", "backend", "devops"]))`
- Define `FILTER_GROUPS` mapping:
  ```typescript
  const FILTER_GROUPS: Record<string, StackFamilyKey[]> = {
    frontend: ["frontend", "mobile"],
    backend: ["backend", "data"],
    devops: ["infra", "integrations"],
  };
  ```
- Compute `activeNodeIds: Set<string>` from activeFilters: gather all families from active groups, filter nodes whose family is in that set OR family === "methods" (always visible)
- In `use-force-layout.ts`, add a `filterNodes` method:
  - Accept `activeNodeIds: Set<string>`
  - Preserve positions of remaining nodes from `nodesRef.current` (map by id)
  - Filter `allNodesRef` (new ref storing original full node list) to only active IDs
  - Filter edges to only those where BOTH source and target are in activeNodeIds
  - Call `sim.nodes(filtered)`, `sim.force("link").links(filteredEdges)`, `sim.alpha(0.5).restart()`
  - Store `allNodesRef` and `allEdgesRef` on first init (copies of the original arrays)
  - CRITICAL: do NOT add activeFilters to the useEffect dependency that creates the simulation. The simulation init must only run once. filterNodes updates the running simulation in-place.
- Return `filterNodes` from the hook alongside positions and drag handlers
- In StackGraph, call `filterNodes(activeNodeIds)` via useEffect when activeFilters changes
- When activeFilters changes, check if focusedId is still in activeNodeIds; if not, call `setFocusedId(null)` to clear stale focus

**E. Render GraphFilters:**

- In `StackGraph.tsx` (or `page.tsx`), render `<GraphFilters>` above the SVG
- Derive pill data from `data.familyColors`: use the color of "frontend" for the Frontend pill, "backend" for Backend, "infra" for DevOps
- Toggle handler: clone activeFilters set, add/remove key, enforce at-least-1 rule, setActiveFilters
