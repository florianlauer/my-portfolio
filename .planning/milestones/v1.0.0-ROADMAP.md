# Milestone v1.0.0: Stack Graph

**Status:** ✅ SHIPPED 2026-04-25
**Phases:** 1–4
**Total Plans:** 7

## Overview

Première milestone du portfolio Stack Graph : transformation de la liste plate "Arsenal" en page dédiée `/stack` avec graph interactif force-directed. Le visiteur peut explorer 39 technologies réparties dans 7 familles, avec relations visuelles, tooltips détaillés, zoom/pan, click-to-focus, filtres par catégorie, et accessibilité complète (clavier + screen reader + reduced motion).

### Phase 3: Interactivity

**Goal:** Visitor can explore the graph through hover, click, zoom, pan, and filtering by domain
**Depends on:** Phase 2
**Requirements:** INTER-01, INTER-02, INTER-03, INTER-04
**Plans:** 2/2 plans complete

Plans:

- [x] 03-01-PLAN.md — Zoom/pan via d3-zoom, click-to-focus highlighting with adjacency dimming
- [x] 03-02-PLAN.md — Rich HTML tooltip, category filter pills with d3-force reflow

**Details:**

- d3-zoom attaché à un `bgRectRef` (rect transparent de fond) — évite les conflits avec le drag des nœuds
- Range zoom 0.5x–3x, double-clic = reset 300ms, transformation stockée en ref + `setAttribute` direct (pas de re-render React 60fps)
- Click-to-focus : adjacency dim via `useMemo(neighborSet)`, transitions CSS 200ms sur les opacités
- Détection click vs drag : threshold 8px euclidien sur `pointerDownPos`
- Tooltip HTML overlay riche : badge niveau, description, tags colorés des connexions, viewport clamping (x) + flip-below (y), animation scale+fade 150ms
- Position du tooltip via `innerGRef.getScreenCTM()` — coords correctes à tous les zoom levels
- Filtres : 3 pills (Frontend, Backend, DevOps) mappant chacun plusieurs `StackFamilyKey` (frontend → frontend+mobile, backend → backend+data, devops → infra+integrations) ; methods toujours visible
- `filterNodes` met à jour la simulation d3-force en place : `sim.nodes()` + force link + `alpha(0.5).restart()` — pas de réinit
- At-least-1 enforcement : impossible de désactiver tous les filtres
- Dépendances ajoutées : `d3-zoom@3`, `d3-transition@3`

### Phase 4: Accessibility

**Goal:** The graph is usable without a mouse and respects user motion preferences
**Depends on:** Phase 3
**Requirements:** A11Y-01, A11Y-02, A11Y-03, A11Y-04
**Plans:** 2/2 plans complete

Plans:

- [x] 04-01-PLAN.md — Reduced motion support: `usePrefersReducedMotion` hook, static d3 layout
- [x] 04-02-PLAN.md — Keyboard navigation with focus ring/tooltips, screen reader list (StackGraphSRList)

**Details:**

- `usePrefersReducedMotion` hook SSR-safe (default `true` pour éviter les flashs d'animation à l'hydratation)
- Branch reduced-motion dans `useForceLayout` : `sim.stop()` + tick loop synchrone jusqu'à convergence — aucune frame rAF
- `simRef` reste `null` quand reduced-motion ; les guards `(!sim)` existants désactivent le drag silencieusement
- `filterNodes` en reduced-motion : sim temporaire convergé puis stocké, sans toucher `allNodesRef`
- Double-clic zoom skip transition 300ms quand reduced-motion actif
- Navigation clavier : `tabIndex={0}` + `role="button"` sur chaque `<g>` SVG, focus ring dashed blanc (`isFocused` prop)
- `onFocus` déclenche le tooltip via `onHoverChange` (même mécanisme que le hover souris)
- Enter/Space sur nœud focus = `onNodeClick` (highlighting d'adjacence)
- `keyboardFocusedId` séparé de `hoveredId` — focus ring vs tooltip découplés
- `aria-hidden="true"` sur le SVG ; `StackGraphSRList` (sr-only `<section>` > `<ul>` > `<li>`) liste les technos actives avec nom, niveau, description, connexions
- SR list reflète l'état des filtres (passe `activeNodeIds`) — synchronisée live
- Outline natif du focus retiré (commit `e585beb`) au profit du ring custom

## Milestone Summary

**Decimal Phases:**

Aucune phase décimale — milestone livrée selon le plan original 4 phases.

**Key Decisions:**

- d3-force + React SVG (~15 KB d-force) plutôt que Canvas/WebGL : accessibilité native (tabindex, focus events), DOM inspectable, suffisant pour 30–50 nœuds.
- Cercles avec icônes centrées plutôt que pills — visuellement plus propre, scale mieux à toutes tailles.
- Drag d3-natif (`fx/fy` + reheat) plutôt que Framer Motion drag — comportement organique : les voisins suivent élastiquement, simulation se restabilise.
- Suppression du micro-movement perpétuel et du spring-back — le drag d3 fournit déjà assez de "vie", le reste devenait du bruit.
- Famille "methods" ajoutée tardivement — propagation type-safe à `StackFamilyKey` partout (graph + Arsenal home).
- d3-zoom attaché à un rect transparent (pas au SVG root) — évite les conflits de pointer events avec le drag.
- ZoomTransform en ref + `setAttribute` direct — évite 60 fps de re-renders React.
- Tooltip positionné via `innerGRef.getScreenCTM()` — coords correctes à tous les zoom levels.
- `filterNodes` met à jour la simulation en place — pas de réinit, animation fluide.
- SSR default `reducedMotion = true` — défaut safe contre le flash d'animation à l'hydratation.
- `<g role="button">` sur SVG avec `eslint-disable jsx-a11y/prefer-tag-over-role` — `<button>` impossible dans SVG.
- `aria-hidden` sur SVG + `StackGraphSRList` (sr-only) — alternative textuelle complète au graph visuel.

**Issues Resolved:**

- Page `/stack` complète avec graph interactif, accessible, performant.
- Tous les requirements DATA, RENDER, PAGE, INTER, A11Y v1 cochés (19/19).
- Outline natif retiré sur focus (fix `e585beb`).
- Hook orphelin `use-micro-movement.ts` supprimé (commit `009f42e`).
- Bugs zoom + drag CTM corrigés en Phase 3 (commit `0dc9434`).

**Issues Deferred:**

- Phase 04 verification status `human_needed` (6 tests runtime — focus ring visuel, OS Reduce Motion, VoiceOver) — pas de gap de code, juste à valider en navigateur réel avant déploiement.
- Plans `03-01-PLAN.md` et `03-02-PLAN.md` non commités (untracked à la clôture) — à committer en post-clôture si souhaité.

**Technical Debt Incurred:**

- Aucune dette technique majeure. Le code est typé, build/lint passent à zéro warning, l'architecture est extensible (POLISH-01 à 04 et MOBILE-01/02 sont prévus pour v1.1+).
