# AGENTS.md

This file provides guidance to coding agents working with code in this repository.

## Project Overview

Personal portfolio site on TanStack Start (React 19, SSR via Nitro), TypeScript, Tailwind CSS v4, shadcn/ui, **use-intl** (FR/EN/DE). Tooling is Vite+ (`vp`) with pnpm. Four routes (each with localized variants): `/` (home), `/a-propos` → `/about` / `/uber-mich`, `/galerie` → `/gallery`, `/stack`.

## Commands

```bash
pnpm install     # or `vp install`
pnpm dev         # vp dev, http://localhost:3000
pnpm build       # vp build, output in .output/ (Nitro)
pnpm start       # serve the production build
pnpm check       # vp check: oxfmt + oxlint + type check (CI gate)
pnpm test        # vp test (Vitest), unit tests in src/**/*.test.ts
pnpm fmt         # vp fmt: format in place
```

`vp check`, `vp test` and `vp build` are the CI gates. Lint and format settings live in the `lint` and `fmt` blocks of `vite.config.ts`.

## Dev Environment

Uses **Nix + devenv** (auto-activated via `devenv hook zsh`). Do not assume global Node.js — Node 22 is provided by devenv, and corepack provides the pnpm version pinned in `package.json#packageManager`. `pnpm-workspace.yaml` holds the pnpm settings: build-script policy and the overrides that point `vite`/`vitest` at the Vite+ builds.

## Architecture

**Routing:** file routes in `src/routes/` (TanStack Router, `routeTree.gen.ts` is generated by `vp dev`/`vp build`; commit it). Every component renders on the server and hydrates on the client, there are no Server Components. Code that touches `window` must run in effects or `useSyncExternalStore` so the server and first client render match.

**Content strategy (post-i18n):**

- **Locale-bound copy** (titles, descriptions, labels, aria-labels) lives in `src/messages/{fr,en,de}.json` — consumed via `useTranslations` in components, or `createTranslator` in route `head()` functions.
- **Locale-agnostic structural data** (URLs, asset paths, IDs, graph edges, ordering) stays in `src/content/*.ts` as typed exports.
- Adding a translation key requires editing **all three** message files. The runtime warns in dev (`!!!ns.key!!!`) if a key is missing.

**Component organization:** Feature-based folders under `src/components/` (e.g. `home-nav/`, `home-sections/`, `language-switcher/`, `site-footer/`, `gallery/`, `stack-graph/`). `src/components/ui/` is the shadcn/ui output directory — add components with `npx shadcn@latest add <name>`.

**Types:** Shared types in `src/types/`. Each content domain has a matching type file. `global.d.ts` augments use-intl's `AppConfig` with the `fr.json` shape, so `t()` keys are checked at compile time. Content ids used in dynamic keys (`StackItemId`, `StackNodeId`, gallery ids) derive from the message keys, so an id without a translation fails the type check.

## i18n

- **Routing:** `src/i18n/routing.ts` defines `locales`, `defaultLocale`, and the typed `pathnames` map. Source paths (`/`, `/a-propos`, `/galerie`, `/stack`) are exported via `SourcePath` and `SOURCE_PATHS` — do **not** duplicate this list elsewhere.
- **Localized URLs:** router routes use source paths (`/$locale/a-propos`). `localeRewrite` in `src/i18n/navigation.tsx`, passed to the router in `src/router.tsx`, maps them to public URLs (`/en/about`) both ways.
- **Locale resolution:** the root route (`src/routes/__root.tsx`) reads the locale from the first URL segment, falls back to `defaultLocale`, and loads that locale's messages (`src/i18n/messages.ts`). `src/routes/$locale.tsx` throws `notFound()` for unknown locales. `/` redirects to the locale negotiated from `Accept-Language` (`src/routes/index.tsx`).
- **Navigation:** use `Link` (takes a source path and an optional `locale`) and `usePathname` (returns the source path) from `@/i18n/navigation`, not TanStack's `Link` directly.
- **Metadata:** `pageHead({ locale, sourcePath, title, description })` in `src/i18n/metadata.ts` returns a route's `head()` entries: title, description, canonical, hreflang alternates (incl. `x-default`), OpenGraph/Twitter title and description. Site-wide tags live in the root route. The sitemap uses the same `buildAlternates` helper.
- **Locale display:** flag/code/native/og labels live in `src/i18n/localeMeta.ts` — single source for the language switcher and footer.
- **`<html lang>`:** set in `src/routes/__root.tsx` from the URL's locale segment (never from a cookie).
- **Adding a route:** add the entry in `routing.ts:pathnames` and in `ROUTE_BY_SOURCE_PATH` (`src/i18n/navigation.tsx`), create `src/routes/$locale/<route>.tsx` with a `head()` built by `pageHead`, add the priority in `src/routes/sitemap[.]xml.ts:PRIORITY_BY_PATH` (TS will require the last two).

## Key Conventions

- **Path alias:** `@/*` maps to `src/*` — always use it for imports.
- **Styling:** Tailwind v4 — uses `@import "tailwindcss"` in `src/styles.css` (via `@tailwindcss/vite`), theming via `@theme inline` with oklch CSS custom properties. No `tailwind.config.js`. Use `cn()` from `@/lib/utils` for conditional classes.
- **Animations:** Scroll reveal via `ScrollReveal` (IntersectionObserver). Parallax via `useScrollY` hook + CSS transforms. `motion` (Framer Motion) is installed for complex animations.
- **SEO:** `head()` per route, JSON-LD in `src/routes/__root.tsx`, `robots.txt` and `sitemap.xml` server routes (multilingual with hreflang `x-default`). The base URL comes from `SITE_URL` (or Vercel's system env) at build time, see `vite.config.ts`.
- **Images:** use `Image` from `@/components/image/Image` for local images. On Vercel it builds a srcset through Vercel Image Optimization (`/_vercel/image`, widths in `widths.ts`); elsewhere it serves the original file. Fonts are self-hosted with `@fontsource-variable`.
- **Accessibility:** Skip-to-content links (translated), ARIA labels (translated), focus-visible rings, ≥44×44 touch targets on interactive elements. Run Lighthouse/axe audits after visual changes.
